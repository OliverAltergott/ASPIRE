# SO101 (LeRobot) with RGB cameras

The SO101 adapter exposes one SO-ARM101 follower through LeRobot 0.4.x with two RGB
cameras (wrist and external) and no depth or camera extrinsics. The CAP boundary uses
five arm joints in radians and a gripper opening from 0 (closed) to 1 (open).
Programs run through ASPIRE's `ProgramExecutor`; `python -m cap_harness.so101` owns
the bus and cameras.

## Start a session

The adapter never calibrates, homes, or changes servo configuration; it needs an
existing LeRobot calibration. OpenCV camera indices can reorder after a camera is
replugged or moved, so grab one frame per index before starting.

```bash
tail -n +1 -f commands.jsonl | PYTHONPATH=src python -m cap_harness.so101 \
  --port /dev/cu.usbmodemXXXX --robot-id my_so101_follower \
  --calibration-dir ~/.cache/huggingface/lerobot/calibration/robots/so101_follower \
  --cameras '{"external": 1, "wrist": 0}' --output runs/so101 \
  --allow-motion --record --stdio > replies.jsonl
```

Append one JSON line per program to `commands.jsonl`, e.g.
`{"program": "result = get_observation()"}`; this file-follow form suits agent shells
that cannot keep a pipe open. Each reply names the CAP trace, the per-camera PNGs and
`view.jpg`, both cameras side by side at 360 px high. Read `view.jpg`, and track
objects numerically with `so101.detect_color` between image checks: hosted models cap
images per request, and per-camera image reads used up that cap in an earlier session.
`--record` writes `session-<time>.mp4` (H.264, 10 fps, cameras side by side), one per
session; join the files of a run with ffmpeg's concat demuxer (`-f concat -c copy`).

Begin with `get_observation()` and then `so101.enable()`. If torque is off, enable
primes goals at the measured pose before enabling torque; if torque is already on, it
adopts the existing goals. Stop with SIGINT. Torque stays on and the arm holds its
pose, without homing or releasing, so a restarted session can adopt it again.

## Agent over MCP (System 2) and SAM3

`--mcp` serves the same tools through ASPIRE's System 2 session and MCP transport at
`http://127.0.0.1:8222/mcp/` (`--mcp-port`), as in [System 2](system2.md) but for one
SO101: `observe` takes the fresh observation that motion requires and returns both
cameras as one image; motion results return text only; YAM programs such as Home are
not offered. `scripts/start_so101_agent.sh [exec] "task"` attaches a fresh Codex agent
with [the SO101 agent guide](so101-agent-guide.md); Claude Code can attach with
`claude mcp add --transport http cap http://127.0.0.1:8222/mcp/`.

`--sam3-url` adds `so101.segment_text(query)`: text-prompted boxes and mask centroids per
camera. SAM3 runs without CUDA through
`python -m cap_harness.providers.sam3.portable --device cpu --port 8114` (gated weights:
`huggingface-cli login` first). On an Apple M5 Pro it takes about 5.5 s per camera and
prompt; MPS fails inside SAM3. ASPIRE's uv configuration pins numpy 1.26 for
Linux simulators; install SO101 extras (`lerobot[feetech]==0.4.4`, `numpy==2.2.6`,
`pycocotools`, `-e third_party/sam3`) into the SO101 environment from outside the
repository so that pin does not apply.

The first autonomous run (Codex, `gpt-6-astra`, high reasoning effort) completed the
[ball-into-cup recipe](../examples/so101/ball_in_cup/TASK_CONTEXT.md) in 12.7 min with 37 tool
calls: about 7 min of agent reasoning, 4.7 min of motion and 1 min of SAM3.

## Interlocks

Every motion call checks the following before writing goals:

- an observation of all cameras was taken within the last 60 s (inspect it first);
- frames from both cameras are fresh now. LeRobot ends a camera's read thread after
  11 consecutive read errors; the next observation restarts it (counted in
  `camera_reconnects`). If the camera still delivers nothing, motion stays blocked:
  restart the session, which always recovered it;
- torque is on, goals were not changed outside the runtime, and tracking is within 5°;
- every waypoint of a call is checked before the first write: at most 5° from the previous
  waypoint (gripper 10 units), the first within 5° of the measured arm, all within
  calibrated limits (`shoulder_lift` stops near
  −107°).

Each call streams its whole path at 50 Hz and `--speed` (default 20°/s; 60°/s gave a
peak tracking error of 3.4°), re-checking torque and tracking (5° + 0.1 s × speed) every
tick, then settles once for at most 0.6 s. At 60°/s, leaving rest for the grasp staging
pose takes 1.8 s; at the original 3°/s with a settle per 3° step it took about 45 s.
A call succeeds when each arm joint is within 2.5° of its target, or the gripper within
2 units. Loaded shoulder and elbow joints sag up to about 1.7° under gravity.
Anything larger is reported as `controller_failed`; inspect for contact.

## Tools

| Tool | Use |
| --- | --- |
| `get_observation`, `get_robot_state`, `get_task_context` | RGB views, measured joints, conventions |
| `move_to_joints`, `so101.move_delta` | absolute radians / relative degrees, ≤5° per call |
| `set_gripper` | opening 0–1, executed in checked steps of ≤0.1 |
| `so101.move_tool(delta_mm, pitch=None)` | straight tool-point line plus optional pitch change, ≤200 mm, chained ≤3° steps, table floor −8 mm |
| `so101.go_to(xyz_mm=None, pitch=None, joints_deg=None)` | joint-space move to an absolute tool pose or five arm joints; use it to leave or return to rest, where tool lines are infeasible |
| `so101.close_until_contact(min_opening=0.1, ease=0.025)` | close until stall; eases the goal below the stalled opening; `contact=False` means nothing grasped |
| `so101.detect_color(hsv_lower, hsv_upper, ...)` | OpenCV-HSV blobs per camera; `min_fill≈0.6` keeps round objects |
| `so101.get_telemetry` | positions, goals, loads, torque, limits, and `urdf_model` tool position/pitch |

## Geometry

Positions come from the URDF model in [`kinematics.py`](../src/cap_harness/so101/kinematics.py),
in millimetres in `so101_base`. They are not an independent calibration:

- The tool point is the URDF `gripper_frame`, near the jaw-tip centre. The table is at
  roughly z = −10 to −5 mm: 26 of 31 recorded ball grasps had the tool between −10
  and +5 mm. The measured tool sits 2–7 mm below the commanded one on loaded poses,
  and up to 11 mm near full reach (radius ~320 mm), so `move_tool` plans from goals.
- Reach at pitch 38°: at z = 50 mm the tool cannot come closer than about 220 mm
  radius (elbow limit); radius 325 mm is still reachable at z = 100–140 mm.
- Heading is `atan2(y, x)`; its sign is opposite to `shoulder_pan`. Pitch is
  `shoulder_lift + elbow_flex + wrist_flex`: 0 points the jaws outward horizontally,
  90 points them straight down.
- With `wrist_roll ≈ −85°` the jaws open tangentially. The jaw-plane normal (tool y) is
  `(sin p, cos p)` in the radial/vertical plane at pitch p. The wrist camera sits on
  its +y side: above the fingers at shallow pitch, radially outward at steep pitch.
  In the wrist image the static jaw is on the left and the moving jaw (servo horn, four
  screws) on the right. Image right is clockwise about the base (positive pan).
- The gripper scale is calibration-specific: a 40 mm ball stalled at 0.20 with load 500.

The external camera has no extrinsics. The robot base pixel plus one known object
position gave a table-plane mapping good to about 15 mm. Parallax dominates for
objects at different heights. Compare a held object with a target only after lowering
it to the target's height.
